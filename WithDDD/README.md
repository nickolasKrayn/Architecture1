# WithDDD

Консольное приложение для расчёта оплаты водителям. Правила предметной области находятся в доменной модели: рейс управляет своим состоянием, тариф представлен объектом-значением, ведомость — агрегатом, а формулы оплаты — политиками.

## Запуск

Откройте `WithDDD.sln` в Visual Studio и нажмите **F5** или **Ctrl+F5**.
Приложение читает `Data/sample.json`, рассчитывает ведомость, выводит начисления и утверждает её.

## Пример расчёта

Для водителя №7 за ноябрь выбраны два подтверждённых рейса:

| Рейс | Расчёт | Сумма |
| --- | --- | ---: |
| 71 | 1000 за рейс + 40 км × 25 | 2000 ₽ |
| 72 | (1000 за рейс + 40 км × 30) × 1,25 за ночную работу | 2750 ₽ |

Итого: **4750 ₽**. Для другого расчёта измените `Data/sample.json` и запустите приложение повторно.
Например, при пробеге 50 км у рейса №71 итог составит 5000 ₽.

## Правила

- В расчёт входят подтверждённые рейсы указанного водителя за выбранный период.
- Начало периода включается, конец исключается.
- Тариф определяется по дате завершения рейса. Новая версия действует с указанного момента.
- Ночная надбавка применяется ко всей оплате за рейс.
- Один рейс нельзя добавить в одну ведомость дважды.
- После утверждения ведомость нельзя изменять.
- Завершение и подтверждение рейса — разные состояния. Пробег можно исправлять до подтверждения.

`Payroll` запрещает дубли рейсов и изменение утверждённой ведомости через свой публичный API. Его коллекция строк доступна только для чтения. Подтверждённый `Trip` запрещает менять пробег.

## Структура

| Каталог | Назначение |
| --- | --- |
| `Domain` | Рейсы, тарифы, ведомость, период и политики расчёта |
| `Application` | Сборка ведомости и взаимодействие с источниками данных |
| `Infrastructure` | Источники рейсов и истории тарифов в памяти |
| `Input` | Чтение JSON и подготовка данных |
| `ConsoleUi` | Вывод ведомости |
| `Data` | Пример рейсов и истории тарифов |

Точка входа — `Program.cs`. Данные хранятся в памяти; запуск не изменяет исходный JSON.
Проект рассчитан на последовательное выполнение. Хранение в БД, конкурентные изменения и запрет повторной оплаты
через разные ведомости не реализованы. Денежные значения вычисляются в `decimal`; при выводе показываются два знака после запятой.
